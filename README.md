## Лабораторная работа №12

### Описание проекта

Мы написали кликер, где пользователь нажимает на изображение и набирает баллы. В зависимости от количества очков меняется оценка, фоновое изображение и цвет интерфейса.

### Цель работы:
Изучить жизненный цикл Activity в Android и научиться правильно
обрабатывать переходы между состояниями. В результате лабораторной работы будет
создано интерактивное приложение "Grade Clicker" (Кликер оценок), которое
демонстрирует работу lifecycle callbacks и сохранение состояния при изменении
конфигурации устройства.


## Контрольные вопросы

### 1. Какие три метода вызываются при запуске приложения?
При первом запуске Activity последовательно вызываются три метода:
1. **`onCreate()`** — Activity создаётся. Здесь происходит инициализация интерфейса и основных компонентов.
2. **`onStart()`** — Activity становится видимой для пользователя, но ещё не активна.
3. **`onResume()`** — Activity выходит на передний план и начинает взаимодействие с пользователем.

### 2. Чем отличается onPause() от onStop()?
- **`onPause()`** вызывается, когда Activity теряет фокус, но остаётся частично видимой (например, при появлении диалогового окна или прозрачной активности). Это лёгкая операция, которая выполняется быстро.
- **`onStop()`** вызывается, когда Activity полностью скрыта другой активностью и больше не видна пользователю (например, при сворачивании приложения или открытии нового экрана).

### 3. Когда вызывается onRestart()?
Метод **`onRestart()`** вызывается перед тем, как остановленная (stopped) Activity снова становится видимой. Это происходит, когда пользователь возвращается в приложение после того, как оно было свёрнуто, но ещё не уничтожено системой. После `onRestart()` всегда следуют `onStart()` и `onResume()`.

### 4. Что происходит при повороте экрана?
При повороте экрана происходит **изменение конфигурации** (configuration change). По умолчанию Android уничтожает текущую Activity (вызываются `onPause()`, `onStop()` и `onDestroy()`) и создаёт её заново (`onCreate()`), подстраивая макет под новую ориентацию. Если состояние не сохранено (например, с помощью `rememberSaveable` или `ViewModel`), все данные будут потеряны.

### 5. В чём разница между remember и rememberSaveable?
- **`remember`** — сохраняет значение только при **рекомпозиции** (перерисовке интерфейса в рамках одного экземпляра Activity). При повороте экрана или другом изменении конфигурации данные сбрасываются.
- **`rememberSaveable`** — сохраняет значение не только при рекомпозиции, но и при **изменении конфигурации** (например, повороте экрана), так как использует `Bundle` для сохранения состояния.

### 6. Почему onCreate() должен вызывать super.onCreate()?
Вызов **`super.onCreate()`** обязателен, потому что он выполняет важную работу по инициализации базового класса `Activity`: восстановление предыдущего состояния, привязку контекста, настройку внутренних компонентов Android. Без этого вызова приложение может работать некорректно или упасть с ошибкой.

### 7. Для чего используется класс Log?
Класс **`Log`** используется для вывода отладочных сообщений в панель **Logcat** в Android Studio. Это помогает разработчику отслеживать выполнение кода, проверять порядок вызова методов и искать ошибки без прерывания работы приложения. Основные уровни: `Log.d()`, `Log.e()`, `Log.i()` и т.д.

### 8. Какой метод вызывается только один раз за время жизни Activity?
Метод **`onCreate()`** вызывается только один раз за весь жизненный цикл Activity (если только она не была уничтожена и не создаётся заново). Он предназначен для однократной инициализации интерфейса и данных.
